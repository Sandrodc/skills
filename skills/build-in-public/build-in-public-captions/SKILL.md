# Build-in-public captions

The media is the post. The caption names what it is and gets out of the way. Reference captions: "Working on some chat cards", "Little details ✍️", "New navigation and player for @elevenreader on Android. Rolling out now.", "Really happy with how these animated icons turned out for a new thing I'm working on. I combined @theo's 'council' skill with my design and animation agent skills to build them…"

## Pick the shape

```
What kind of post is it?
├── A small detail or micro-interaction → 2–5 words. ("Little details", "Hover states for the queue")
├── Work in progress on a component    → "Working on <thing>" (+ optional half-sentence of what's next)
├── Shipped                             → "<What> for <product/platform>. <Status>." ("Rolling out now.", "Live on iOS.")
└── Made with an interesting method/tool → 1 sentence of how it turned out + 1 sentence of how it was made, crediting the tool/person
```

## Rules

- Max 2 sentences; under 120 characters unless it's the method shape. Every extra word competes with the video.
- Never describe what the video visibly shows ("Here you can see the card expand…"). The viewer is watching it.
- Never: hashtags, "Excited to announce", "🚀", "🧵", "Thoughts?", engagement bait. They signal marketing; the references signal craft.
- At most 1 emoji, at the end, only if it adds tone.
- Sentence case; plain, confident verbs. No hedging ("kind of", "trying to").
- Tag a person or tool only if it actually contributed — the Emil post credits @theo because the skill shaped the result.
- Name the product only if it's public. Unannounced → "a new thing I'm working on".

## Output

Give 3 variants: the shortest possible, the one matching the shape above, and one that adds the single most interesting "how" detail. Mark the one you'd post.
